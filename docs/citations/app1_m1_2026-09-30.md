# APP1 citation checks, family M1: on-device and edge learning in 2025–26, and the cost of hyperparameter sweeps (2026-09-30; R10)

This is stage C of `Applied_Suite/APPLICATIONS_DECLARATION.md`, family **M1**. It covers:
- on-device and edge learning that ships in phones, wearables, hearing aids, cars and robots;
- what vendors say they do (on-device personalisation, federated learning, private compute);
- the constraints they state (energy, memory, privacy, no hyperparameter tuning on device);
- the published evidence on what hyperparameter sweeps cost in fine-tuning and continual learning.

The dossier records sources and verified quotes. It is a note, not evidence (R8): it grades no application and quotes no
number from the ledger. Rows of the record are named by id only. The grading is `Applied_Suite/checks/applications.py`'s.

**How the sources were handled.** Every source was fetched on the day (2026-09-30) through the session proxy with curl
(TLS verified against the proxy CA bundle):
- **arXiv:** the abstract page, for the current version and the version history; then the PDF of the current version.
- **CVF open access:** the paper page and the camera-ready PDF.
- **Vendor web pages:** the HTML as served.
- **The Apple developer article:** its documentation JSON (the HTML page is rendered by script).

How the text was extracted:
- **PDFs:** pymupdf 1.28.2.
- **HTML:** BeautifulSoup `get_text('\n')`, after `script`, `style` and `noscript` were dropped.
- **The Apple JSON:** flattened to text, with each inline reference replaced by its title.

Where the files are: outside the repository, under `/tmp/claude-0/app1_src/m1/` (`src/` the fetched files, `txt/` the
extracted text, `search/` the saved arXiv and CVF landing pages). The sha256 of every file is in
`/tmp/claude-0/app1_src/m1/SHA256SUMS.txt` (80 files); the sha256 of each fetched source is also in the table below.

**Verification.** The claims are in `Applied_Suite/checks/claims_m1.py`: 40 claims, 87 quotes, 26 raw files. They were
checked with a scratch copy of `Open_Bottlenecks/checks/verify.py`, pointed at `claims_m1.py` with root
`/tmp/claude-0/app1_src`. Its normalisation is unchanged: NFKC, whitespace collapsed, a line-break hyphen read as kept or
rejoined, and `[...]` checked fragment by fragment.
- **Result:** "quotes found verbatim: 87 of 87 (claims 40; raw files 26, missing 0); not found 0; missing 0".
- **Negative control:** one number was altered in m1:20 ("22% of clients" changed to "32% of clients"). The check then
  read "86 of 87", with m1:20 quote 0 NOT FOUND, as it should.
- **One fragment split:** in m1:28 quote 3 a hyperlink boundary leaves a space before a comma ("Live API ,"). The quote
  is therefore given as two fragments joined by `[...]`; the page's words are unchanged.

APP1 has no pinned check yet. A family verifier that reads claims_m1..m3, like OB1's `verify.py`, is the pinned form.

**Rules for the numbers.**
- Every number in a quote is the source's own, on its own protocol, and sources are not comparable with each other.
- Arithmetic in an `agent_note` is the agent's, on quoted numbers only. For example, m1:12's "24 times one model" is
  2880 h divided by 120 h, both quoted.
- A description of a mechanism is the agent's reading of the fetched text. The quotes are the evidence.
- Code links were **not checked**.
- "Not found" in this sweep is never "novel".

**The sweep-cost evidence** (general; bears on the Energy and Compute dimensions of every application):
- **Linear cost:** cost is linear in the number of hyperparameter experiments (m1:13).
- **One tune is many runs:** tuning for a new dataset was estimated at 24 runs of the model (m1:12).
- **Budget decides the winner:** the tuning budget changes which model wins (m1:14).
- **Fine-tuning energy is a sum:** it is spread over many actors and runs (m1:15).
- **Continual learning:** the usual sweep costs a full pass over the stream per configuration, and a deployed learner
  cannot run it at all (m1:16). Tuning inside the evaluation scenario inflates reported performance (m1:18).
- **The comparator:** the cheapest realistic baseline is first-task HPO, and it is not reliably worse (m1:17).

For APP1's Energy and Compute grades, this means a saving must name its comparator. Each comparator gives a different
number:
- a full sweep (m1:12, m1:16);
- first-task HPO (m1:17);
- vendor defaults (m1:30);
- fleet-level tuning (m1:2).
No source here measures a sweep-free continual-learning weight in deployment.
