## A. Drift compensation and transport of stored statistics (N1, N5)

### 1. SDC, semantic drift compensation (Yu et al., CVPR 2020)

- **Identifier:** arXiv:2004.00440, current version **v1** (1 Apr 2020; the only version listed), comment "Accepted at CVPR2020", fetched 2026-09-30. Lu Yu, Bartłomiej Twardowski, Xialei Liu, Luis Herranz, Kai Wang, Yongmei Cheng, Shangling Jui, Joost van de Weijer.
- **Integrity:** PDF (v1) `pdf_2004.00440v1.pdf` sha256 946d8a1bd98ed61438fb8d19b2bad12c74ed6b1b20cacb1d7ee0064083186257; abstract page sha256
  276b391c4cf4355c6c7c6d5c50840100a09e67d9d6800f5be9e45f6b389e8f37.
- **Mechanism:** store one mean per class; during a new task measure how each current-task embedding moves between the old and new model (a sparse vector field) and move each stored mean by a proximity-weighted average of those vectors. **Reference points:** current-task data. **Stores:** class means.

> we propose a new method to estimate the drift, called semantic drift, of features and compensate for it without the need of any exemplars. We approximate the drift of previous tasks based on the drift that is experienced by current task data.

> We aim at reducing the error that drift causes and propose a drift compensation to update previously computed prototypes. The main idea is to estimate the unknown drift according to the known drift of the current data during the training of the current task.

- **Reading.** N1 **states** (stored prototypes corrected by the measured movement of reference points). N2: the counter-case; the reference points are current data, and the paper says so. (Claims rrm:0.)

### 2. LDC, learnable drift compensation (Gomez-Villa et al., ECCV 2024)

- **Identifier:** arXiv:2407.08536, current version **v1** (11 Jul 2024; the only version listed), comment "Accepted to ECCV 2024", fetched 2026-09-30. Alex Gomez-Villa, Dipam Goswami, Kai Wang, Andrew D. Bagdanov, Bartlomiej Twardowski, Joost van de Weijer.
- **Integrity:** PDF (v1) `pdf_2407.08536v1.pdf` sha256 2405a7e62e67a8a7d4ccc573ce8aa782460775aa0a4e3de5bc648d373d357a77; abstract page sha256
  43e3b00a0812dd947d5a02e39c32aac8fca3eb62849f2ac48087cf3b53e43a4c.
- **Mechanism:** after each task, fit a projector (best: one linear layer) from old-backbone to new-backbone features on the current task's data, and apply it to the stored class means. Supplementary Table 6 projects N stored features per class instead of the mean. Fig. 4 compares with NME, which recomputes old means from stored exemplars. **Stores:** class means (or N features).

> We do not need to store any old images or features, or use any labels of the current data; we simply store only the old class prototypes and update them using the learned current task projector.

> The projector pt F can be any trainable mapping function. However, we found that a linear layer performs best in this task (see section 4.4).

> We compare the performance of LDC against Nearest-Mean of Exemplars (NME) which directly uses exemplars for old class prototype compensation and is explored in exemplar-based methods [10,43]. While it is easy to predict the updated positions of the old prototypes using original samples of old classes by NME, it is very challenging without exemplars in our settings.

> Without exemplars, pf only learns the projection from current task data. Consequently, due to biases in the current data, updates to some old class prototypes may not be perfect.

- **Reading.** N1 **states**, with a linear old-to-new map, the same algebraic form as RRM's transport. N2 **close**: it names NME as the standard exemplar route ("directly uses exemplars for old class prototype compensation") and names the bias of fitting on current data; NME recomputes a mean from kept rows, it does not transport a stored statistic of the whole class. N5 **close**: stored old-class features transported by a linear map, fitted on current data; no gain over the mean. (Claims rrm:1, rrm:11, rrm:28.)

### 3. ADC, adversarial drift compensation (Goswami et al., CVPR 2024)

- **Identifier:** arXiv:2405.19074, current version **v1** (29 May 2024; the only version listed), comment "Accepted at CVPR 2024", fetched 2026-09-30. Dipam Goswami, Albin Soutif-Cormerais, Yuyang Liu, Sandesh Kamath, Bartłomiej Twardowski, Joost van de Weijer.
- **Integrity:** PDF (v1) `pdf_2405.19074v1.pdf` sha256 8e118b149315b07b17561c8447c7572b7b9136dca6528902d7cc451697470c1a; abstract page sha256
  592ba426bfc7fd5806fe7b8ddf8816b8d7ec5132688d0ab32abe66f56fe679d3.
- **Mechanism:** perturb current images adversarially until their old-model embeddings sit at an old class prototype; measure how those pseudo-exemplars move to the new model; move the prototype by that amount. **Stores:** class means.

> To address this problem of feature drift estimation for exemplar-free methods, we propose to adversarially perturb the current samples such that their embeddings are close to the old class prototypes in the old model embedding space. We then estimate the drift in the embedding space from the old to the new model using the perturbed images and compensate the prototypes accordingly.

> Now, the drift from old to new feature space is estimated using these adversarial samples, which serve as pseudo-exemplars for the old classes. We hypothesize that the pseudo-exemplars behave like the original exemplars in the feature space, and thus we exploit them to measure the drift.

- **Reading.** N1 **states**. N2 **bears**: the drift is measured on points placed at each old class, i.e. the role RRM gives to kept anchors, but the points are generated from current data each task, and the paper hypothesises that they "behave like the original exemplars". (Claims rrm:2, rrm:14.)

### 7. TRIPS, multivariate prototype representation (Peng et al., arXiv 2023)

### 9. MPT, missing prototype tracking via barycentric reconstruction (Jang et al., arXiv 2026)

- **Identifier:** arXiv:2609.12771, current version **v1** (11 Sep 2026; the only version listed), comment "9 pages, 7 figures", no journal reference, fetched 2026-09-30. Hanju Jang, Gyeongmin Han, Sungmin Lee, Kichang Lee, Chunghan Lee, JeongGil Ko.

- **Mechanism:** in cross-vehicle federated learning, when the vehicle holding most of a class departs, that class's prototype is written at departure as barycentric weights over the remaining classes' prototypes (in-span) plus a residual (out-of-span); each round, the remaining classes' prototypes are re-embedded with the updated backbone and the departed prototype is rebuilt from its stored weights, with the residual adapted from covariance changes and calibrated with the few remaining samples. **Stores:** class-level prototypes and covariances; no raw data.

The second is an out-of-span component, captured by a residual that cannot be spanned by remaining classes. - **Reading.** N1 **states**. ## Is the RRM transport itself published? (N5)

**Not found in this sweep.** No source found stores old-class feature statistics (or samples of them) and carries them to the
current feature space by the measured movement of a few **kept** reference rows, whether by a relation (regression) map or by
anchor-relative coordinates. Each part is published separately:

- **Transporting stored class statistics (Gaussians, Gram matrices, means) by a linear or ridge-regularised map between the old
  and new feature spaces:** LDC (linear projector), DPCR (linear projection), GATF (ridge-regularised generalised least
  squares), AdaGauss (adapter), TRIPS (drift-shifted Gaussians, replayed), MEA (stored features, MLP). All fit the map on
  **current-task** data.
- **Holding content relative to references and rebuilding it from the references as seen now, with an in-span / out-of-span
  split:** MPT (federated; references are the remaining classes' live prototypes; residual adapted), IRP (across models).
- **Fitting a linear map between two latent spaces on a few paired anchors and applying it to other points:** Maiorca et al.
  2023 (across models, not across one learner's training).
- **Using kept old-class rows to place old prototypes after drift:** iCaRL's NME and CoPE (recomputation from the kept rows,
  not transport of a stored statistic of the whole class).

The closest sources, with the exact quote:

> We estimate this linear relationship using paired current-task features

> we formulate the estimation of Pt, bt as a ridge-regularized Generalized Least Squares

(GATF, arXiv:2606.25347 v2: the nearest transport operation; the pairs are current-task features.)

> The key idea is to decompose the rare-class prototype into two parts. The first is an in-span component, expressed by its barycentric relationship to the remaining-class prototypes. The second is an out-of-span component, captured by a residual that cannot be spanned by remaining classes. After each FL round, remaining vehicles re-embed local data using the updated backbone and report class-level prototypes and covariances.

(MPT, arXiv:2609.12771 v1, 11 Sep 2026: the nearest form of the owner's reading; the references are not kept anchors.)

> The transformation T , derived solely from the subset of corresponding points, provides a robust and versatile foundation for model reuse and interoperability in diverse machine learning contexts.

(Maiorca et al., arXiv:2311.00664 v2: the transport step across models.)

"Not found" is never "novel": the sweep was by keyword on arXiv only, over one day; conference-only papers, feature-space
replay in other fields (speech, graph, federated and retrieval continual learning were only touched), and code were not
searched systematically. The combination (a kept-anchor reference set in place of current-task pairs) is a small change to
GATF, LDC or DPCR, and the declaration's own ablation (RRM − STALE, and a current-data-fitted variant if the investigator adds
one) is what would show whether it matters.
